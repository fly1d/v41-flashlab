# V41 FlashLab 销售手册

这份手册用于销售“模型迁移决策”，而不是销售一个通用榜单。对外沟通必须保持可核对：没有真实运行记录时，不发布模型胜率、节省比例或性能领先结论。

## 一句话定位

用客户自己的脱敏样本，在同一规则下比较当前模型与候选模型，材料齐备后 3 个工作日给出迁移、按任务路由或暂缓建议，并保留可复算的逐样本证据。

## 优先客户画像

优先联系满足至少两项的团队：

- 已经为 OpenAI、Claude、Qwen 或 DeepSeek API 持续付费。
- 有客服知识库、长文档问答、结构化抽取、代码助手或 Agent 工作流。
- 最近遇到模型涨价、延迟波动、上下文不足或供应商切换需求。
- 有 20 条以上可脱敏、可判断对错的真实样本。
- 有技术负责人能够提供端点并确认业务门槛。

暂不优先：只想看免费榜单、没有可用样本、要求用未脱敏数据、要求保证降本比例，或希望评测方承担生产系统改造责任的客户。

## 标准销售漏斗

1. **公开证据**：发布方法、原始记录和至少一个负面发现，吸引有真实迁移问题的团队。
2. **15 分钟资格判断**：确认现有模型、样本、业务损失、决策期限和数据边界。
3. **付费迁移体检**：标准范围服务费 ¥9,800，避免首单陷入无限定制；税费、API 费用与付款节点书面确认。
4. **结果复盘**：把建议拆成可迁移任务、保留任务和待补证据。
5. **企业试点或持续回归**：只有体检发现明确业务价值时升级。

## 资格判断问题

1. 现在生产上用哪些模型和端点？每月大致请求量和费用是多少？
2. 哪种失败最贵：答错、超时、格式违规、数据风险还是人工返工？
3. 是否有 20–50 条能够脱敏且有标准答案或明确 rubric 的样本？
4. 谁负责确认答案和最终迁移门槛？
5. 为什么现在考虑 V4.1-Flash，最晚何时必须做决定？
6. 样本能否发送到第三方 API，还是必须在客户环境运行？
7. 若结果建议“部分路由”或“暂缓”，客户是否仍接受报告价值？

最后一题必须问。不能接受独立结论的客户不适合购买独立评测。

## 发现会结构

- 0–3 分钟：确认触发事件和决策日期。
- 3–8 分钟：确认任务、流量、当前成本及主要失败。
- 8–12 分钟：确认样本、答案负责人、端点和数据边界。
- 12–15 分钟：给出适配判断和下一步，不在会中承诺未核算的定制工作。

会后只输出三种状态：适合 ¥9,800 标准体检、需要企业试点报价、不适合当前服务。

## 签约与开工门禁

成交文件采用三件套，不用一张售前确认单承担全部法律功能：

1. [`customer-proposal-template.zh-CN.md`](customer-proposal-template.zh-CN.md)：订单、固定范围、排期、价格和验收。
2. [`standard-service-terms-template.zh-CN.md`](standard-service-terms-template.zh-CN.md)：付款、取消、知识产权、保密、责任和争议解决。
3. [`data-processing-addendum-template.zh-CN.md`](data-processing-addendum-template.zh-CN.md)：仅在服务方接触未公开数据、个人信息或调用第三方 / 境外端点时启用。

首单开工前必须同时满足：真实经营与收款主体已确认；订单与适用条款已签署；首笔款到账；样本授权和脱敏已确认；两个端点通过 smoke；API / GPU 预算、数据路径和业务门槛已冻结。任何一项缺失都不开始接收数据或承诺交付日期。

## 常见异议

| 异议 | 回应 |
| --- | --- |
| 官方已经有榜单，为什么还要付费？ | 官方榜单回答通用能力，迁移体检回答你的任务、端点和业务门槛。交付物包含逐样本证据与失败分类。 |
| 能保证更便宜或更好吗？ | 不能预设结论。独立评测的价值正是尽早发现不值得迁移，避免生产事故和无效改造。 |
| 我们不能把数据发给你 | 可以先由客户脱敏；更严格的场景可在客户控制环境运行 CLI，另行确认交付方式。 |
| ¥9,800 太贵 | 免费基线可自行运行；付费部分是业务样本设计、同场运行、失败复核和迁移决策，而不是调用几次 API。 |
| 能否顺便改生产系统？ | 标准体检不含生产改造。评估通过后，可单独报价企业试点或交给客户现有实施团队。 |
| 可以只告诉我哪个模型最好吗？ | 没有脱离工作负载的“最好”。我们会按任务给出迁移、路由或暂缓建议。 |

## 商业纪律

- 不接受模型厂商付费改变排名或隐藏失败案例。
- 厂商赞助、免费额度和商务关系必须在报告中披露。
- 不使用“完全安全”“保证降本”“行业第一”等无法审计的表述。
- 不把 12 条合成业务样本包装成全面能力结论。
- 客户密钥不进入聊天、邮件、表单或交付文档。
- 未经客户书面同意，不公开其名称、样本、结果或合作关系。
- 对外发布、发送私信、邮件或报价前，必须由项目所有者确认发送身份、目标名单和最终文本。

## 首批 14 天执行节奏

| 时间 | 动作 | 完成标准 |
| --- | --- | --- |
| 第 1–2 天 | 配置合法 API 额度，跑 V4.1-Flash 与一个生产基线 | 两侧原始记录、固定 suite SHA、失败样本齐全 |
| 第 3 天 | 发布一份含负面案例的首发报告 | 方法、环境、原始记录和限制可访问 |
| 第 4–7 天 | 从公开公司渠道筛选 30 个目标团队 | 每个目标有业务触发事件和对应角色，不收集私人联系方式 |
| 第 5–10 天 | 分两批发送经确认的 10–15 条定向沟通 | 记录送达、回复、资格会和拒绝原因 |
| 第 8–14 天 | 完成 3–5 次资格会并争取首个标准体检 | 范围确认单、付款主体、数据边界和排期齐全 |

首轮只优化三个数字：有效回复率、资格会率和标准体检成交率。浏览量不是主要销售指标。

# V41 FlashLab 模型迁移评估服务

V41 FlashLab 用客户自己的脱敏业务样本，对比当前模型与候选模型，回答三个问题：哪些任务值得迁移，哪些任务应继续保留现有模型，以及上线前必须补哪些验证。

这不是通用排行榜，也不出售模型名次。所有结论都绑定具体样本、端点、参数和验收门槛。

## 主产品：模型迁移体检

### 客户提供

- 最多 50 条已脱敏、拥有合法评测权限的业务样本。
- 当前基线模型和 V4.1-Flash 的合法可用端点及 API 额度；密钥应由客户在自己的运行环境配置。
- 每类任务的最低质量、最高延迟、token 预算、成本估算上限和硬性失败条件。
- 一名能够确认业务答案和处理争议样本的负责人。

### 我方完成

1. 检查样本可评分性、数据边界和模型端点配置。
2. 锁定 suite 版本、参数、重复次数和判定规则。
3. 在同一数据与预算下运行当前基线和候选模型。
4. 分别汇总质量、端点可靠性、延迟、TTFT、token 使用和成本估算。
5. 对错误答案、格式违规、拒答、超时和端点故障进行分类。
6. 给出“迁移、部分路由或暂缓”的按任务建议及回退条件。

### 标准交付物

- 版本化评测 suite 和 SHA-256。
- 逐次请求 JSONL 原始记录；是否保留输入由客户的数据策略决定。
- Markdown / JSON 汇总及基线对比报告。
- 关键失败样本清单和人工复核记录。
- 一页决策摘要：推荐路由、主要风险、试点门槛与回退路径。
- 60 分钟线上结果复盘。

### 验收标准

服务验收的是评测工作是否按约定范围完整、可复算，而不是候选模型必须达到某个分数。

- 约定样本均有结果或明确错误记录，不静默删除失败样本。
- 报告数字能够从交付的原始记录复算。
- 基线与候选使用相同 suite 字节；任何端点或参数差异均在报告中披露。
- 结论逐项对应客户预先确认的门槛。
- 对不可比较或证据不足的事项明确写出限制，不强行给出赢家。

成本仅依据双方确认的端点价目与记录到的 token 用量估算，不等同于供应商最终账单；缓存计费、失败请求、阶梯价和价格变动需要在报告中单列假设。

## 数据与安全边界

- 不接收密钥、未脱敏客户原文、未公开源代码或无权用于评测的数据。
- 若样本需要发送给第三方模型 API，必须由客户确认数据条款、区域和传输范围。
- 可在客户控制的环境运行 CLI，使端点凭据不离开客户环境。
- 默认评分器不执行模型生成的任意代码；真实代码仓库任务需要另行约定隔离环境。
- 当前 `agent` 轨道只评估单轮工具意图与结构化输出，不宣称完整工具执行或多步轨迹能力。
